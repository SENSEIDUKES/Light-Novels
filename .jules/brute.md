## 2026-08-15 - Native Input Keyboard Confirmation Handling   **Learning:** Modals that rely on custom text inputs (like typing 'DELETE' to confirm) can completely block keyboard-only users if they expect 'Enter' to submit the form without explicit `onKeyDown` listeners when there is no surrounding `<form>` tag catching the submit event. The auto-fill helper buttons also need redundant keyboard listeners if `e.preventDefault()` is used to stop event bubbling or default native double-clicks.   **Action:** When auditing or adding custom destructive UI patterns, always add `onKeyDown={(e) => { if (e.key === 'Enter') { ... } }}` handlers to both the input and any helper buttons to ensure the expected native submission workflow works.
