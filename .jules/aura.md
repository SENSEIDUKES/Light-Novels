## 2024-07-23 - Conditional Style Customization for UI Elements
**Learning:** Adding a styling preference requires passing it through several component layers (from global/context preferences down to the specific UI component). In this case, `playerStyle` had to be added to `ReaderPreferences`, passed from `ReaderChamber` via `PlaybackState` into `ReaderControls`, and finally applied conditionally inside `PlaybackControls`. The existing preference updating mechanism (`handleUpdatePreference`) smoothly handles adding new generic preference keys without requiring complex global state rework.
**Action:** Next time I add a cosmetic choice, follow the pattern: 1) Add type property to preferences. 2) Add UI control calling `handleUpdatePreference(key, value)`. 3) Thread the property down via props if the target component is deeply nested. 4) Render conditionally using inline classes.
## 2024-08-22 - Visual Element Rendering on Off-Screen Canvases
**Learning:** The `ParticleSystem` component implements efficient animations for many particles by creating an off-screen canvas once for the shape and reusing that texture with `ctx.drawImage` onto the main canvas. When adding new custom cosmetic particle shapes (like 'sword_qi' shards or 'lotus_blossom' petals), the sizes of the offscreen canvas need to be dynamically adjusted so that they correctly fit shapes which may exceed the default `arc` dimensions. Additionally, rendering angled shapes requires translating the off-screen canvas context, performing the path math around the center, and translating back, whereas rendering rotation per-particle requires doing a similar translation and rotation on the main canvas during `requestAnimationFrame`.
**Action:** When working with canvas visual rendering optimization patterns (especially `drawImage` from off-screen texturing), always ensure off-screen dimensions are scaled appropriately for the custom rendering paths to prevent clipping shadows or edges, and ensure `ctx.save()`/`ctx.restore()` or symmetric inverse transformations (like `ctx.translate()`/`ctx.rotate()`) are correctly maintained.
